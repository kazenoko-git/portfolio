Hi! I’m **Talos 1**. I have sixteen tiny digital neurons, one shared arithmetic unit, a little SPI mailbox, and absolutely no idea what your cat is saying.

I was built as a first neuromorphic hardware project: a small circuit that keeps a little memory of event order. The point was to learn what happens when a software idea gets translated into registers, clocks, wires, and a very finite silicon budget. The point was **not** to claim I can diagnose your heart, recognize every gesture, or understand the neighbor’s dog.

This is a design report with the jargon translated into human. If you are ten, welcome. If you are a Verilog wizard, please enjoy my tiny hats.

## Fast tour: what did I actually build?

Talos 1 is a **16-neuron, recurrent, leaky integrate-and-fire reservoir**. That sounds like a sentence assembled by a committee of robots. Here is the kid-friendly translation:

- **16 neurons:** sixteen little number buckets, each keeping an 8-bit signed value from −128 to +127.
- **Integrate:** a new input can add to the number in a bucket.
- **Leak:** the number slowly shrinks, so yesterday’s excitement eventually gets forgotten.
- **Fire:** when the number reaches a threshold, the neuron emits a one-bit spike and resets its bucket to zero.
- **Recurrent:** neurons can react to spikes from the previous step. A ripple can make more ripples.
- **Reservoir:** the circuit makes a changing pattern; a separate, ordinary computer can learn to read that pattern.

Talos is not a tiny computer running a tiny copy of a brain. It is a deliberately small pattern-making circuit. It does not train itself. It does not contain the final task classifier. Its job is to turn an event stream into a state that a host computer may find easier to classify.

### The “brain inspired” bit, with fewer dramatic robes

In a software recurrent neural network, many operations can happen in parallel on a GPU. Talos 1 uses a much simpler fixed network. It has a ring-like pattern of excitatory and inhibitory connections, plus a longer-range connection five positions away. Connection signs are limited to −1, 0, or +1, all scaled by a shared setting. That means the circuit can add or subtract a chosen amount without a general-purpose multiplier.

The topology is fixed in the RTL. You can adjust the common weight scale, threshold, leak mode, and external input bits; you cannot redraw the network through SPI. “Reservoir” describes the role this fixed network plays in the experiment, not a claim that it is a biologically accurate brain.

## The memory trick: buckets, leaks, and a reset button

Each neuron stores its membrane value, `V`. On a step, it computes:

<div class="talos-equation" role="math" aria-label="new value equals old value minus leak plus incoming synaptic current, then clamp to eight-bit signed range; if it reaches threshold, emit a spike and reset to zero">
  <span>new bucket</span><b>=</b><span>old bucket</span><b>−</b><span>leak</span><b>+</b><span>incoming nudges</span><span class="equation-foot">Clamp to −128…+127. If the result ≥ threshold: <strong>spike!</strong> Then reset to zero.</span>
</div>

The leak choices are arithmetic right shifts: no leak, shift by 3, by 2, or by 1. A shift is cheap hardware. It is also chunky integer math. For example, a value of 7 shifted right by 2 becomes 1, then 0 on a later step. Real exponential decay is smooth; these integer buckets descend by little stair-steps and may settle at a small residue.

If the value reaches the threshold, Talos emits a spike and resets that neuron to zero. A spike is a one-bit event, like a tiny “ding!” The membrane value is different: it is the bucket’s current fill level. Talos exposes both, because throwing away the bucket and keeping only the dings can lose useful information.

### One shared calculator, sixteen turns

Here is the main area-saving trick: there are sixteen stored neuron values, but **only one LIF arithmetic unit**. A sequencer visits neuron 0, then 1, then 2 … then 15. One time-step therefore takes sixteen update cycles after it starts. It is a classroom calculator passed down a row: less hardware, more waiting.

At the beginning of a step, Talos freezes the previous step’s spike vector. Every neuron uses that same old snapshot while the new step is calculated. Without the snapshot, neuron 15 might see freshly updated spikes from neurons 0–14 while neuron 0 saw only the previous step. That would make the answer depend on the order of the queue, which is a very silly kind of physics.

While the update is running, `busy` is high and another step trigger is ignored. The host should wait until `busy` clears before starting another step or treating the output vector as a completed result. Spike bits are updated as the sequencer visits neurons; read the final result after the step is done.

### The wire-in / wire-out mailbox

The top-level design connects an SPI slave, a small register file, and the reservoir. SPI Mode 0 carries configuration and observations. The register interface supports these main controls:

| Address | What it does | Plain translation |
| --- | --- | --- |
| `0x00` | Step / soft reset; read busy bit | “Take one step”, “start over”, and “are you done?” |
| `0x01` | Signed 8-bit firing threshold; reset default `+32` | How full before a bucket splashes |
| `0x02` | Signed 8-bit weight scale; reset default `+12` | How big each synaptic nudge is |
| `0x03` | Eight external input bits | Events can directly nudge neurons 0–7 |
| `0x04–0x05` | Sixteen latched spike bits | Which neurons fired this step |
| `0x06` | Leak selector; reset default `>>> 2` | How quickly buckets forget |
| `0x10–0x1F` | Sixteen signed membrane values | How full each bucket is |

The step can also be triggered by a rising edge on the dedicated `ext_tick` pin. Seven spike outputs go to `uo[1]` through `uo[7]`, eight more to `uio[0]` through `uio[7]`, and neuron 15 has no dedicated spike pin: read it over SPI. Tiny pin budget, tiny plot twist.

`info.yaml` declares a 16 MHz clock and a 1×1 tile. That is the project configuration, **not** proof that the full design is physically safe at 16 MHz. A simulation clock is not a timing signoff report, and an ASIC layout is not the same thing as an FPGA board test.

## What the tests really tested

The source branch includes Verilog RTL and cocotb tests driven with Icarus Verilog. The testbench talks to the top module using the same pins and SPI registers the design exposes. That is useful: it checks that the pieces can work together in simulation. It does not place Talos on a desk and ask it to listen to a heartbeat.

The Talos 1 benchmark review records a rerun on **22 October 2026**, revision [`9985bf6`](https://github.com/kazenoko-git/Talos/tree/talos_1), with **16 tests passing**: ten benchmark demos, five functional tests, and a separate direction-classifier test. These are software simulations and host-side Python readouts. No results below are measurements from fabricated silicon.

### A fair reading of the carnival

The strongest useful story is not “Talos solved ten applications.” It is “the circuit produces state that changes with its inputs, and small readouts can fit several toy tasks.” The weak spots are just as educational:

| Demo | What happened | What it does **not** show |
| --- | --- | --- |
| Regression | Tuned settings reached R² = 0.945 on a repeated waveform, using subthreshold membrane values. | General regression skill on new signals. The comment called the input rate coding, but it is a quantized binary channel pattern. |
| Forecasting | One-step R² = 0.563 and MSE = 0.0361 on one repeated period-10 sawtooth. | A general memory limit or strong multi-step forecasting. A persistence baseline should be checked. |
| Denoising | The chosen noisy example went from 60% noise to 40% reconstruction error. | Successful denoising: this setup made the example worse. The test only checks output length. |
| Anomaly detection | 100% on repeated `1010` versus `1100` patterns. | Unseen anomaly families, jitter, or a measured false-alarm rate. The “unseen” wording in the old log is too generous. |
| Sensor fusion | 100% on four repeated Boolean input combinations at one fixed delay. | A learned coincidence window across changing delays, missing events, and timing noise. |
| Direction / localization | 100% on two opposite sweeps. | Proof that temporal memory was needed: the final input channel alone identifies which sweep just happened. |
| Temporal segmentation | 95% for quiet versus burst phases. | A difficult segmentation task: the current input directly announces the label. |
| Embeddings | Repeated identical inputs had cosine similarity 1.000; two selected motifs had 0.000. | Robust embeddings across jitter, noise, many classes, or held-out examples. |
| Control | Simulated error fell from 2 to about 0. | Learned temporal control: the reservoir is reset before each action, and a simple proportional controller is the obvious baseline. |
| Impulse decay | The state faded from 21 to a stable total residue of 7. | Autonomous spiking or a useful oscillation. The seeded state stays subthreshold. |

**What is cosine similarity?** Imagine laying two arrows on graph paper. If they point in the same direction, the score is near 1; at right angles it is near 0. Identical repeated patterns getting 1.000 is a useful “the circuit is repeatable” check. One selected pair getting 0.000 is not a certificate for a universal embedding machine.

**What is R²?** It compares a prediction with a very lazy guess that always predicts the average. A score of 1 is perfect, 0 is no better than that average guess, and below 0 is worse. So 0.945 is promising for that particular test; 0.563 is a modest one-step result, not a crystal ball.

The test script’s 60-trial forward/reverse classifier also splits repeated copies of the same two three-event sequences into training and test groups. It resets the network for each sequence. That is a handy wiring demonstration, but “unseen test trials” means new repetitions, not new sequence types. Also, the final channel already says forward or reverse. The best next test would give both classes the same final event and ask whether the earlier order still helps.

## So, what did the tiny chip teach us?

### Good lessons, in very small shoes

1. **The state is useful to inspect.** Keeping sixteen membrane values made it easy to see the dynamics, including when the network stayed subthreshold. The state is part of the story, not just the fireworks.
2. **Integer details matter.** Right shifts are cheap, but negative values round in a particular way and small positive values can stick. A cartoon “leak” is not enough; the exact arithmetic rule changes behavior.
3. **One calculator saves area and costs time.** Sharing the LIF unit avoids sixteen copies of the arithmetic, but every step takes sixteen visits. Area and throughput are having a very polite argument.
4. **A demo can pass and still ask an easy question.** Repeated toy data checks that a path works. Held-out patterns, noise, simple baselines, and honest metrics check whether the result means more.
5. **A simulation is not a chip measurement.** The 16-test rerun is simulation evidence. It tells us about the RTL under that environment, not power, physical maximum speed, or behavior on real hardware.

### What I would test next

- Make forward and reverse sequences share the same first and last channel, so order really matters.
- Hold out entire pattern shapes, not merely more copies of a pattern the readout has already seen.
- Add jitter, missing events, distractors, and multiple random seeds.
- Compare with tiny simple baselines: last input, event counts, persistence, and a hand-built temporal filter.
- Report both success and failure, with number of examples and exactly what was held out.
- Measure the actual critical path, area, and power from the relevant physical-design reports; test the SPI interface on a real board when one is available.

That is how “this little thing passed a test” grows into “we know what this little thing can do.” Tiny steps. Extremely tiny neurons.

## The honest postcard

Talos 1 is a small, fixed-topology, 16-neuron spiking reservoir in Verilog. It uses 8-bit signed membrane state, configurable shift leak and threshold, a shared time-multiplexed LIF unit, a fixed recurrent pattern, and an SPI register interface. Its tests show functional simulation behavior and several toy readout experiments. They also show that some tasks are too easy, one demo got worse, and integer arithmetic leaves a residue.

It is a first hardware design and a good pile of questions. It is not evidence of medical accuracy, useful audio recognition, measured low power, 16 MHz physical operation, or working fabricated silicon. Talos 2 is a separate follow-on design; it is not the subject of this post.

If you remember one thing, let it be this: **Talos does not know what a pattern means. It keeps a tiny changing memory, and lets a separate readout take a guess.**
