<div class="talos-lede">

Can a circuit with sixteen neurons remember which event came first? Talos 1 is a **spiking reservoir in Verilog** built to explore that question. Sixteen neurons hold the state, and they take turns using one shared calculator. The simulations show how that state changes. The harder question is whether it helps a computer tell similar event sequences apart.

## The memory trick: buckets, leaks, and a reset button

Each neuron stores a membrane value, `V`. Think of it as a bucket: incoming current can fill it, the leak drains it, and reaching the threshold makes the neuron fire and empty the bucket. The hardware updates the stored value once per step.

<div class="talos-equation" role="math" aria-label="new value equals old value minus leak plus incoming synaptic current, then clamp to eight-bit signed range; if it reaches threshold, emit a spike and reset to zero">
  <span>new value</span><b>=</b><span>old value</span><b>−</b><span>leak</span><b>+</b><span>incoming current</span><span class="equation-foot">Clamp to −128…+127. At or above threshold, emit a spike and reset to zero.</span>
</div>

With leak enabled, the circuit subtracts `V >>> k` on each update, where `k` is 1, 2, or 3. The arithmetic right shift uses integer math. In the decay test below, the value stops at 7 because `7 >>> 3` evaluates to 0.

### SPI register interface

The top-level design connects the SPI peripheral, the register file, and the reservoir. The host uses SPI Mode 0 to read state and write configuration.

| Address | Register | Reset default |
| --- | --- | --- |
| `0x00` | Step and soft reset commands, busy status on read | — |
| `0x01` | Signed 8-bit firing threshold | `+32` |
| `0x02` | Signed 8-bit weight scale | `+12` |
| `0x03` | Eight external input bits for neurons 0–7 | — |
| `0x04–0x05` | Sixteen latched spike bits | — |
| `0x06` | Leak mode | `>>> 2` |
| `0x10–0x1F` | Sixteen signed membrane values | — |

The step can also be triggered by a rising edge on the dedicated `ext_tick` pin. Seven spike outputs go to `uo[1]` through `uo[7]`, eight more to `uio[0]` through `uio[7]`, and the host reads neuron 15’s spike bit over SPI.

`info.yaml` specifies a 16 MHz target clock and a 1×1 tile.

## What the tests really tested

The cocotb testbench drives the Verilog top module through its pins and SPI registers in Icarus Verilog. On **22 October 2026**, revision [`9985bf6`](https://github.com/kazenoko-git/Talos/tree/9985bf6) passed **16 tests**: ten benchmark demos, five functional tests, and one direction classifier. The results come from RTL simulation, with Python readouts running on the host where needed. Timing and power on fabricated silicon remain unmeasured.

The scorecard includes accuracy, R², cosine similarity, and error. Each metric applies to its own task.

### What each test measures

| Demo | Result | Limits of the setup |
| --- | --- | --- |
| Regression | Tuned settings reached R² = 0.945 on a repeated waveform, using subthreshold membrane values. | General regression skill on new signals. The comment called the input rate coding, but it is a quantized binary channel pattern. |
| Forecasting | One-step R² = 0.563 and MSE = 0.0361 on one repeated period-10 sawtooth. | A general memory limit or strong multi-step forecasting. A persistence baseline should be checked. |
| Denoising | Accuracy against the clean signal fell from 60% for the noisy input to 40% for the reconstruction. | The assertion checks output length only. |
| Anomaly detection | 100% on repeated `1010` versus `1100` patterns. | Unseen anomaly families, jitter, or a measured false-alarm rate. The “unseen” wording in the old log is too generous. |
| Sensor fusion | 100% on four repeated Boolean input combinations at one fixed delay. | A learned coincidence window across changing delays, missing events, and timing noise. |
| Direction / localization | 100% on two opposite sweeps. | Proof that temporal memory was needed: the final input channel alone identifies which sweep just happened. |
| Temporal segmentation | 95% for quiet versus burst phases. | A difficult segmentation task: the current input directly announces the label. |
| Embeddings | Repeated identical inputs had cosine similarity 1.000; two selected motifs had 0.000. | Robust embeddings across jitter, noise, many classes, or held-out examples. |
| Control | Simulated error fell from 2 to about 0. | Learned temporal control: the reservoir is reset before each action, and a simple proportional controller is the obvious baseline. |
| Impulse decay | The state faded from 21 to a stable total residue of 7. | Autonomous spiking or a useful oscillation. The seeded state stays subthreshold. |

**Cosine similarity** compares the direction of two vectors. Identical repeats scored 1.000, and one selected pair of patterns scored 0.000. The test covers repeatability and separation for that pair.

**R²** compares the model’s squared prediction error with the error from predicting the average every time. A score of 1 is perfect. A score of 0 means the errors are equal. A negative score means the model has higher error.

The 60-trial direction test splits repetitions of two three-event sequences into training and test sets and resets the reservoir before each sequence. The final input channel identifies the class by itself.

## What did the chip teach us?

The impulse test exposed a property of the integer update rule: small positive values can keep their state after input stops. Reading the membrane registers made that behavior visible even when no neuron fired.

### What I would test next

- Use sequences with the same first and last events and swap the middle events. Compare the readout with an event count baseline.
- Hold out entire pattern shapes, not merely more copies of a pattern the readout has already seen.
- Add jitter, missing events, distractors, and multiple random seeds.
- Compare forecasting with persistence, which predicts the last observed value, and compare denoising with a simple temporal filter.
- Report both success and failure, with number of examples and exactly what was held out.
- Measure the actual critical path, area, and power from the relevant physical-design reports; test the SPI interface on a real board when one is available.
